StudyCoach

An adaptive study platform designed to turn personal notes and PDFs into focused, interactive revision sessions.

PythonFastAPIChromaDBSQLAlchemyStreamlitAgno
Source repository ↗ No live demo published

Problem & user context

Turning a long document into an effective revision plan takes time, and generic quizzes may not reflect the material a student actually needs to learn. StudyCoach explores a flow where learners provide their own notes and practice against questions grounded in that content.

User need

Move from static notes to an interactive session without manually authoring every practice question.

Product objective

Generate relevant practice from uploaded material and adjust question difficulty based on a learner's responses.

Architecture & data flow

The documented design combines a retrieval-augmented generation pipeline using ChromaDB with three focused agents. FastAPI exposes the application services; Streamlit provides the user-facing prototype.

Constraints & trade-offs

Grounding vs. flexibility

Retrieval gives the model relevant source context, but answer quality still depends on document extraction and retrieval quality. A generated answer should not be treated as automatically correct.

Agent responsibilities

Guide, Eval and Contest separate session flow, evaluation and question practice. The added structure makes roles clearer but requires explicit coordination between them.

Adaptation signal

The Adaptive Engine uses learner performance to tune difficulty, rather than relying on a fixed sequence of questions.

Prototype boundary

The repository describes an application prototype; published deployment, usage and learning-outcome benchmarks are not available.

Results & lessons

3documented agents: Guide, Eval and Contest
1retrieval-backed learning flow built around a learner's own material
0published production usage or learning-outcome benchmarks

The project description states that notes and PDFs can become interactive revision sessions in seconds. No independent timing study or learner-outcome measurements are published, so no performance claim is made here.

The main design lesson is to treat generated content as a learning aid with traceable source context, and to keep retrieval, orchestration and adaptive difficulty as separate concerns.
